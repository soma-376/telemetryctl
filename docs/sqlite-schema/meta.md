# `meta`

스키마 초기화기가 버전을 확인하기 전에 만드는 키-값 테이블이다. 보존 정책의 삭제 대상이 아니다.

## 컬럼

| 컬럼 | 타입 | 필수 여부·기본값 | 설명 |
|---|---|---|---|
| `key` | `TEXT` | 필수 기본 키 (`NOT NULL`) | 메타데이터 항목을 식별하는 고정 키. 애플리케이션 계약상 필수 |
| `value` | `TEXT` | 필수 | 키에 대응하는 값. 항목별 형식은 키 계약을 따른다 |

## 키 계약

| 키 | 값 형식 | 소유자와 의미 |
|---|---|---|
| `local_schema_version` | 10진수 정수 문자열 | 스키마 초기화기가 기록하는 고정 버전 `1` |
| `installation_id` | 문자열 | enrollment 설치 ID 사본. v1 도메인 DDL에는 연결 컬럼이 없음 |
| `retention_days` | 10진수 정수 문자열 | 기존 런타임이 기록한 보존 기간 값 |
| `last_rollup_at` | UTC unix 초 문자열 | **마지막으로 저장이 성공한 시각.** 별도 롤업 테이블은 없다 ([ADR 0009](../adr/0009-로컬-저장-모델은-세션-턴-이벤트-계층으로-관리한다.md)) |

## 키·관계·운영

| 항목 | 내용 |
|---|---|
| 생성 시점 | 도메인 스키마 초기화 전 `CREATE TABLE IF NOT EXISTS`로 생성 |
| 관계 | 다른 테이블과 외래 키 관계 없음 |
| 보존 | prune 대상이 아니며 데이터베이스 수명 동안 유지 |
| 변경 규칙 | 임의 키를 추가하지 않고 저장소가 허용하는 고정 키만 사용 |

`last_rollup_at`의 키 이름을 바꾸지 않은 이유는 기존 설치의 GUI와 `status` 출력이 이 키를 읽고
있고, 두 값이 뜻하는 바(데이터가 얼마나 신선한가)가 같기 때문이다. 데몬은 `Write`가 성공할
때마다 이 값을 갱신한다.

개발 DB를 삭제하고 재생성하면 이 테이블의 메타데이터도 함께 초기화된다.

## 참고용 DDL

```sql
CREATE TABLE IF NOT EXISTS meta (
  "key"  TEXT NOT NULL PRIMARY KEY,
  value  TEXT NOT NULL
);
```
