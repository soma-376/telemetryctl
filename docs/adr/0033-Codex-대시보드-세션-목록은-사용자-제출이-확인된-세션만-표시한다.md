# 0033. Codex 대시보드 세션 목록은 사용자 제출이 확인된 세션만 표시한다

## Status

Accepted

## Context

[ADR 0032](0032-Codex-프롬프트-출처를-JSONL로-보강하고-단일-워커로-복구한다.md)는 저장된 실제 Codex 턴의 `client_submitted/finalized`만 사용자 프롬프트로 세도록 정했다. 그러나 세션 목록 자체의 자격을 정하지 않아, 내부 작업 또는 미분류 턴만 있는 Codex 세션이 Home과 Activity에 남고 목록의 세션 수·활성 벤더 표시에도 반영될 수 있다.

이 결정은 telemetryctl의 로컬 대시보드 조회에만 적용한다. JSONL 분류, SQLite 스키마, 로컬 API 필드와 다른 레포의 계약은 변경하지 않는다.

## Decision

- Home의 최근 세션과 Activity 세션 목록에서 Codex 세션은 **그 세션에 속한 저장된 실제 Codex 턴 중 `client_submitted/finalized`가 하나 이상 있을 때만** 표시한다. 턴 본문이 `NULL`이거나 원문이 purge되었어도 출처·처리 상태가 확정돼 있으면 자격을 유지한다. 연결이 ambiguous여도 최종 분류가 `client_submitted/finalized`라면 포함한다. pending·retrying 또는 다른 최종 분류만 있는 세션은 제외한다. Claude Code를 비롯한 다른 벤더의 기존 세션 목록 규칙은 유지한다.
- 이 자격은 세션의 **전체 턴**을 대상으로 판정한다. 날짜 필터는 기존대로 세션 시작 시각에 적용한다. Activity에서는 자격 판정을 검색·정렬·페이지 제한 전에 적용하여 반환 행, `has_more`, 커서가 같은 모집단을 가리키게 한다. Activity 응답에 새 총 건수 필드를 추가하지 않는다.
- Activity의 **Codex** 프롬프트 원문 검색은 자격 있는 `client_submitted/finalized` 턴만 대상으로 한다. 다른 벤더의 기존 프롬프트 검색과 제목·작업 경로·파일명 검색은 유지한다. `matchedSources`의 프롬프트 출처 표시는 같은 검색 자격과 일치해야 한다. 원문이 없으면 원문 검색에 일치하지 않지만 세션 표시 자격은 바뀌지 않는다.
- Home의 전체 세션 수, 진행 중 세션 수, 활성 벤더는 같은 목록 자격을 반영한다. 최근 세션·건수·활성 벤더를 한 응답에서 읽을 때 동일한 DB 스냅샷을 사용하여 서로 다른 자격 상태가 섞이지 않게 한다.
- 전체 토큰·비용·호출·활동시간은 내부 작업과 미분류를 포함한 기존 전체 저장 데이터에서 계산한다. 사용자 프롬프트가 없는 Codex 세션을 목록에서 제외해도 그 사용량과 활동시간을 삭제하거나 재분배하지 않는다.
- 범용 세션 저장·조회 경로 전체에 필터를 강제하지 않는다. CLI·트레이·설정의 원시 조회는 기존 범위를 유지한다. 세션 ID를 지정한 직접 상세 조회와 이미 열려 있는 상세 화면도 유지한다. 공용 조회 헬퍼를 쓰더라도 대시보드 목록용 자격 적용 범위를 명시적으로 분리한다.
- Home·Activity의 기존 30초 polling, 수동 새로고침, 창이 다시 보일 때의 재조회 동작을 유지한다. 자격이 나중에 확정되면 다음 조회 결과에 반영하고, 재분류로 `finalized`에서 `retrying`으로 되돌아가면 다음 목록 조회에서 숨긴다. 이미 열려 있는 상세는 유지한다. 몇 초 이내 표시 같은 새 완료 시간 보장은 두지 않는다. DB 구조, API wire 형식, 분류기는 이 결정 때문에 바꾸지 않는다.

## Alternatives Considered

### A. 프롬프트 건수만 제한하고 Codex 세션 행은 모두 표시한다

- 장점: 세션 목록 조회는 바꾸지 않아도 된다.
- 단점: 내부 작업만 있는 세션이 목록·건수·활성 벤더에 계속 나타난다.
- 탈락 이유: 목록의 의미가 사용자 제출이 확인된 Codex 세션이라는 요구와 맞지 않는다.

### B. 저장소의 모든 세션 조회에서 같은 자격을 강제한다

- 장점: 하나의 기본 필터로 처리할 수 있다.
- 단점: CLI·트레이·설정의 원시 조회와 ID 직접 상세 조회까지 바꾸며, 수집된 전체 사용량을 진단할 경로도 좁힌다.
- 탈락 이유: 이번 결정은 대시보드 목록의 표시 범위에 한정된다.

## Consequences/Tradeoffs

### Positive

- Home·Activity의 Codex 세션 행과 세션 수가 확인된 사용자 제출을 같은 기준으로 나타낸다.
- 검색·페이지 제한·Home 건수 및 요약이 동일한 자격 집합을 사용한다.
- 수집과 전체 사용량은 유지하면서 목록의 노이즈만 줄인다.

### Negative

- JSONL 보강이 지연되면 세션이 목록에 늦게 나타날 수 있다.
- 목록과 직접 ID 상세 조회, 원시 조회의 세션 범위가 의도적으로 달라진다.
- 전체 사용량 합계는 표시된 세션 행의 합계와 달라질 수 있다.

## Acceptance Criteria

- 사용자 제출이 확정된 실제 턴이 0개인 Codex 세션은 Home 최근 세션과 Activity 목록·건수에서 제외되고, 한 개 이상이면 포함된다. 분류가 늦게 확정된 경우 다음 기존 재조회에서 나타난다.
- 원문 `NULL`·purge와 ambiguous 연결의 `client_submitted/finalized`는 목록 자격을 잃지 않는다. 프롬프트 검색과 `matchedSources`는 자격 있는 원문에만 일치한다.
- Activity의 검색·정렬·페이지 제한·`has_more`·커서와 Home의 전체·진행 중 세션 수·활성 벤더를 같은 자격으로 검증한다. 한 응답의 관련 Home 값은 같은 DB 스냅샷에서 일치한다.
- 다른 벤더, CLI·트레이·설정 원시 조회, 직접 ID 상세 조회 및 열린 상세는 기존 동작을 유지한다. 전체 토큰·비용·호출·활동시간도 보존한다.
