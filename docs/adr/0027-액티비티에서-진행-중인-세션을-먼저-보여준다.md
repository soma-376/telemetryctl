# 0027. 액티비티에서 진행 중인 세션을 먼저 보여준다

## Status

Accepted

## Context

액티비티는 시작 시각 내림차순이라 오래전에 시작한 진행 중 세션이 종료된 세션 아래로 밀린다.
목록은 keyset 페이지네이션을 사용하므로 화면에서 받은 일부 행만 재정렬하면 해결되지 않는다.

## Decision

- ADR 0021의 DB 생명주기를 따른다. `ended_at IS NULL`인 세션을 먼저 보여준다.
- 진행 중 세션은 마지막으로 알려진 활동 시각 내림차순, 종료된 세션은 시작 시각 내림차순이다.
  같은 시각이면 세션 ID 내림차순으로 정한다. 시각 미관측은 0으로 처리한다.
- 정렬과 커서는 진행 여부·정렬 시각·ID의 같은 세 값을 사용한다.
  기간 필터는 기존 시작 시각 기준을 유지하며 검색·벤더·프로젝트·상태 필터를 먼저 적용한다.
- 화면은 진행 중 세션을 날짜 그룹 밖의 목록 맨 위에 별도로 배치한다. 상태별 헤더와
  스크롤 고정은 사용하지 않으며, 종료된 세션에만 기존 시작 날짜 구분을 적용한다.
  페이지 사이에 상태가 변해 재등장한 ID는 한 번만 보여준다.
- 페이지 요청 전체를 고정 스냅샷으로 보장하지 않는다. 상태·활동 갱신으로 커서 앞에 이동한
  세션은 기존 자동 갱신 또는 사용자 새로고침으로 첫 페이지부터 다시 조회한다.
- 로컬 API와 GUI 바인딩을 함께 갱신한다. DB 스키마와 서버 계약은 바꾸지 않는다.

## Alternatives Considered

- 프런트에서만 정렬하면 아직 불러오지 않은 진행 중 세션을 맨 위에 놓을 수 없다.
- 페이지 전체를 고정 스냅샷으로 유지하면 수집 중 상태를 제때 반영하기 어렵고 저장·만료 관리가 추가된다.

## Consequences/Tradeoffs

### Positive

진행 중인 작업을 먼저 찾을 수 있고, 고정된 데이터에서는 페이지 경계에서도 중복·누락 없이 조회한다.

### Negative

활동 갱신에 따라 진행 중 영역의 순서가 바뀐다. 페이지 사이의 변경은 새로고침 전까지 일부 늦게 보일 수 있다.
이전 커서와 형식이 달라 GUI와 데몬을 함께 갱신해야 한다.

## Acceptance Criteria

진행·종료 혼합, 최근 활동과 시작 시각이 다른 세션, 동률·NULL 시각, 필터·한 행씩 페이지 이동,
상태 변경 후 첫 페이지 재조회와 GUI 빌드를 검증한다.
