# 0001. 로컬 OTLP 수신기를 인라인 프록시로 두고 재배선은 opt-in 으로 한다.

## Status
Accepted — 단, **"재배선은 opt-in, 기본 OFF" 부분은 [0006](0006-로컬-파이프라인을-opt-out으로-전환하고-OTel-설정을-고정한다.md) 이 대체한다** (PROJ-45).
인라인 프록시 토폴로지, `localhost` 표기 제약, 두 리스너 구성, §5.4 상한선은 그대로 유효하다.

## Context
PROJ-11 은 Claude Code 와 Codex 의 OTel 설정을 회사 Collector 로 **직결**시키는 것까지 끝냈다.
이 구조에서는 데이터가 전부 회사 서버로만 흐르고 로컬에는 아무것도 남지 않는다.
즉 **개발자 본인이 자기 사용량을 볼 방법이 없다.** PROJ-36 의 GUI 대시보드는 이 상태에서는 채울 데이터가 없다.

`docs/installation-architecture.md` §4.5 「제품화 이후」(466-483행)는 이미 같은 토폴로지를 서술해 두었다.

```text
Codex / Claude Code
→ localhost agent
→ OS Credential Manager에서 토큰 조회
→ 회사 Collector 전송
```

같은 절은 "로컬 agent는 설치, 업데이트, 자동 실행, 장애 복구, 보안 관리가 추가되므로 MVP에는 과할 수 있다"며
이를 미뤄두었다. PROJ-36 은 그 판단을 뒤집어 MVP 로 당겨온다 — 로컬 화면이 티켓의 산출물이기 때문이다.
§4.5 가 부수적으로 언급한 "설정에 장기 토큰 대신 로컬 endpoint 만 들어간다"는 이득도 그대로 따라온다.

동시에 §5.4 「Collector 장애가 개발을 방해하면 안 됨」이 이 결정의 상한선이다.
경로 중간에 프로세스를 하나 더 끼우는 일이므로, 그 프로세스가 개발 도구를 느리게 만들면 결정 자체가 무효다.

마지막으로 **주소 표기에 계약 제약이 있다.**
`internal/contract/manifest.go:88` 의 `validOTLPEndpoint` 는 `http://` 를 **리터럴 호스트 `localhost`** 에만 허용한다.

```go
return parsed.Scheme == "https" || (parsed.Scheme == "http" && parsed.Hostname() == "localhost")
```

`contracts/enrollment-manifest.schema.json:36` 의 정규식 `^(https://|http://localhost(?::[0-9]+)?(?:/|$))` 도 동일하다.
따라서 §4.5 가 예시로 적어 둔 `http://127.0.0.1:4318` 은 **지금 검증을 통과하지 못한다.**

## Decision
- 데몬이 loopback OTLP/HTTP 수신기를 띄우고, 받은 시그널을 로컬에 집계·저장한 뒤 회사 Collector 로 **전달**한다.
  수신과 전달을 한 프로세스에서 처리하는 **인라인 프록시**다. 별도 사이드카나 브릿지를 두지 않는다.
- ~~벤더 재배선은 `telemetryctl local enable` **opt-in 이고 기본값은 OFF** 다.
  데몬이 죽어 있는 동안 재배선된 상태면 텔레메트리가 유실되므로, 자동 실행 등록 없이 기본 ON 으로 갈 수 없다.~~
  → **ADR 0006 이 대체한다.** enroll 이 자동 배선하고 `local disable` 이 탈출구다. 여기서 지적한 유실 위험은
  없어진 것이 아니라 **완화만 된 상태**로 남아 있다 — enroll 이 데몬 미기동을 경고하고, 자동 실행 등록은
  여전히 후속 티켓이다 (ADR 0006 의 Negative 첫 항목).
- 벤더 설정에는 반드시 `http://localhost:<port>` 로 쓴다. `validOTLPEndpoint` 를 넓히지 않는다 —
  서버 저장소와의 공유 계약이라 별도 티켓이 필요하다.
- `localhost` 가 `::1` 로 풀릴 수 있으므로 수신기는 `127.0.0.1` 과 `[::1]` **두 리스너를 하나의 `*http.Server`** 에 물린다.
  `net.Listen("tcp", "localhost:port")` 는 한쪽만 바인딩해 절반의 사용자가 조용히 깨진다.
  기동 시 모든 리스너가 loopback 인지 단언한다.
- §5.4 를 지키기 위해: 핸들러는 인증 → 본문 읽기 → 유계 채널 non-blocking 전송까지만 하고 응답한다.
  큐가 가득 차면 **`429` 가 아니라 `200` + `PartialSuccess`** 로 답한다.
  `429` 는 exporter 재시도를 유발해 Claude Code 종료를 지연시킨다. 텔레메트리 손실은 허용, 개발 도구 지연은 불허.
- 포트 기본값은 4318 이고, 사용 중이면 임의 포트로 폴백한 뒤 벤더 설정을 재병합한다. `--listen` 을 명시했으면 하드 실패.
- manifest 의 `otlp.protocol` 이 `grpc` 면 `local enable` 을 명확한 에러로 거부하고 기존 직결 경로를 유지한다.

## Alternatives
### A. 회사 Collector 직결을 유지하고 로컬 화면은 서버 API 로 채운다
- 장점: 클라이언트에 새 네트워크 표면이 생기지 않는다. 수신기·인증·포트 충돌·프라이버시 집행이 전부 불필요하고, PROJ-11 구조를 그대로 둔 채 GUI 만 붙이면 된다.
- 단점: 화면이 서버 가용성과 서버 조회 API 완성에 종속된다. 오프라인·사내망 밖에서는 자기 데이터도 못 본다. 무엇보다 §4.6 정책상 프롬프트 원문과 tool details 는 회사가 수집하지 않으므로, 서버에는 작업 제목·파일 변경 목록을 만들 원천 자체가 없다(ADR 0003).
- 탈락 이유: 개인이 보려는 데이터의 절반이 회사가 의도적으로 수집하지 않기로 한 데이터다. 서버를 경유하는 한 그 데이터는 존재할 수 없고, 존재하게 만들면 §4.6 위반이다.

### B. 벤더가 회사와 로컬 양쪽으로 이중 export 하게 한다
- 장점: 로컬 데몬이 죽어도 회사 수집이 끊기지 않는다. 프록시가 경로 중간에 없으니 §5.4 리스크가 원천적으로 사라지고, 재배선 실패 시 롤백할 것도 없다.
- 단점: Claude Code 와 Codex 의 OTel exporter 설정은 시그널당 endpoint 를 **하나만** 받는다(`OTEL_EXPORTER_OTLP_ENDPOINT`). 두 목적지를 동시에 지정할 방법이 설정 표면에 없다.
- 탈락 이유: 구현 난이도가 아니라 **벤더 설정 표면의 제약**이라 우회가 불가능하다. 시그널을 갈라 로그만 로컬로 보내는 식의 편법은 화면에 필요한 메트릭을 잃는다.

## Consequences/Tradeoffs
### Positive
- 로컬 화면이 회사 서버 가용성과 무관하게 동작한다. 오프라인에서도 자기 데이터를 본다.
- 회사 Collector 로 나가는 본문을 **우리 코드가 통제**하게 된다. 로컬 agent 가 프라이버시 집행 지점이 된다(ADR 0003).
- §4.5 가 지적한 "설정 파일의 평문 장기 토큰" 문제가 완화된다. 벤더 설정에는 로컬 endpoint 와 loopback 전용 ingest 토큰만 남고, 회사 토큰은 데몬 메모리에만 존재한다.
- 중복 제거(§5.5)와 고카디널리티 정리를 회사 Collector 이전 단계에서 한 번 더 할 수 있다.

### Negative
- 데몬이 실행 중이 아니면 재배선된 벤더의 텔레메트리가 통째로 유실된다.
  - 완화: ~~기본 OFF~~(ADR 0006 이 opt-out 기본 ON 으로 바꿨다), `local enable` 시 데몬 상태 확인, `status` 에 로컬 파이프라인 블록 표시. ~~자동 실행 등록을 선행 조건으로 후속 티켓에 등록한다.~~
  - **PROJ-55 (ADR 0007) 로 자동 실행 등록이 생겼다.** `telemetryctl autostart enable` 이 launchd LaunchAgent / systemd user unit 을 등록하고 `enroll` 이 best-effort 로 호출한다. 남은 노출은 등록할 수 없는 환경(Windows·systemd 없는 리눅스)과 재시작으로 낫지 않는 영구 실패뿐이다.
- 로컬에 인증이 붙은 HTTP 표면이 생긴다.
  - 완화: loopback 바인딩 단언 + bearer 토큰(`crypto/rand` 32B, `subtle.ConstantTimeCompare`) + `X-Pulsemetry-Local: 1` 요구 + `OPTIONS` 는 `405`, CORS 헤더 없음. 토큰 권한은 "이 PC 에 텔레메트리 쓰기"뿐이다.
- 포트 4318 은 흔한 OTLP 기본값이라 충돌 가능성이 있고, 폴백하면 벤더 설정 재병합이 뒤따른다.
- 리스너가 둘이라 "로컬에서 동작하더라도 한쪽 스택에서만 깨지는" 회귀가 가능하다. 리스너 loopback 단언과 수신기 테스트로 막는다.
- `grpc` manifest 를 쓰는 설치는 이 기능을 아예 쓸 수 없다.

## Follow-up
- **완료** — **데몬 자동 실행**(launchd / systemd user unit / 작업 스케줄러). `local enable` 기본 ON 의 필수 선행 조건이자 Settings 「시작 프로그램」 토글의 구현이었다. **PROJ-55 에서 macOS·리눅스를 구현했다** (`internal/autostart`, ADR 0007). Windows(작업 스케줄러)는 PROJ-56 으로 남아 있다.
- `contracts/enrollment-manifest.schema.json` 과 `validOTLPEndpoint` 에 `127.0.0.1` 허용 추가 — 서버 저장소와 협의가 필요하다. 그 전까지 `localhost` 표기를 유지한다.
- **gRPC 상위 전달** — 지금은 `grpc` manifest 를 거부하는 것으로 대신한다.
- Windows + WSL 이중 설정에서 같은 이벤트가 양쪽 수신기로 들어오는 경우는 `dedup_key` 유니크 제약이 창 내 중복만 잡는다. 알려진 한계로 문서화한다.
