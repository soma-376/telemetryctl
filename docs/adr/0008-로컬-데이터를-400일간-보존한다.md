# 0008. 모든 로컬 데이터를 400일간 보존한다.

## Status
Accepted

## Context
ADR 0002와 ADR 0003은 `events`·`event_content`·`tool_events`를 기본 30일, 세션·롤업·벤더
데이터를 400일 보존하는 계층형 정책을 정했다. 30일과 400일은 실제 디스크 증가량을 관측한 뒤
재검토하기로 한 MVP 임시값이었고, 사전에 합의된 제품 정책은 아니었다.

PROJ-71에서 팀은 이벤트 계층의 30일 제한을 폐기하기로 합의했다. 원문을 포함한 이벤트는 사용자
장치에만 남고 회사 Collector로 전달되지 않으므로, 세션 상세를 30일 만에 잃게 만드는 별도 제한의
효용이 낮다. 무기한 보존은 로컬 디스크가 유한하므로 채택할 수 없다.

## Decision
- `events`·`event_content`·`tool_events`·`sessions`·`session_files`·`mcp_session_usage`·
  `rollup_hourly`·`vendors`를 모두 **400일간 보존**한다.
- 보존 기간은 사용자 설정이 아닌 고정 제품 정책으로 둔다. `--retention-days`,
  `state.json`의 `local.retention_days`, 계층별 `RetentionPolicy`를 제거한다.
- 설치 상태 스키마를 5로 올린다. 스키마 4의 `local.retention_days`는 읽을 때 무시하고,
  데몬이 마이그레이션 결과를 저장할 때 제거한다.
- SQLite 스키마는 바꾸지 않는다. `meta.retention_days`와 대시보드 JSON의 `retention_days`는
  기존 GUI 호환성을 위해 유지하고, 모든 로컬 데이터에 적용된 값 `400`을 기록한다.
- prune은 하나의 400일 컷오프를 사용한다. 이벤트 원문은 FTS5 정합성을 위해 `event_content`를
  `events`보다 먼저 지우고, 세션은 `last_event_at`을 기준으로 지운다. 전체 삭제는 한 트랜잭션에서
  수행하고 세션 종속 행은 `ON DELETE CASCADE`로 정리한다.
- 이 결정은 ADR 0002의 계층별 보존 결정과 ADR 0003의 원문 30일 보존 조항만 대체한다.
  두 ADR의 SQLite 선택, 로컬 원문 저장, 상위 전달 제거 결정은 계속 유효하다.

## Alternatives
### A. 기존 30일/400일 계층을 유지한다
- 장점: 원문과 이벤트가 차지하는 디스크와 평문 보유 기간을 줄인다.
- 단점: 30일이 지나면 세션 수치는 남아도 검색·툴 타임라인·원문이 사라진다.
- 탈락 이유: 30일은 합의된 요구가 아니며, 로컬에서 장기 세션 상세를 제공하려는 제품 정책과 맞지 않는다.

### B. 기본값만 400일로 바꾸고 사용자 설정을 유지한다
- 장점: 기존 CLI와 상태 파일 인터페이스가 유지된다.
- 단점: 기존 설치의 30일 값과 임의 오버라이드가 계속 적용되어 모든 데이터를 400일 보존한다는 정책을 보장하지 못한다.
- 탈락 이유: 보존 기간을 사용자 선택이 아닌 단일 제품 정책으로 합의했다.

### C. 무기한 보존한다
- 장점: 사용자가 직접 지우기 전까지 모든 이력을 유지한다.
- 단점: 이벤트와 원문이 계속 증가해 로컬 디스크를 무제한 사용한다.
- 탈락 이유: 유한한 사용자 장치에서 운영 가능한 상한이 필요하다.

## Consequences/Tradeoffs
### Positive
- 최대 400일의 세션에서 검색·툴 타임라인·원문을 세션 수치와 같은 기간 동안 조회할 수 있다.
- 보존 상수와 컷오프가 하나가 되어 코드·상태·CLI 사이의 불일치가 사라진다.
- 기존 데이터베이스에 DDL 마이그레이션 없이 적용할 수 있다.

### Negative
- 평문 원문과 이벤트의 최대 보유 기간이 30일에서 400일로 늘어나 디스크 사용량과 로컬 노출 기간이 증가한다.
  - 완화: 원문 항목당 16KB 캡, `--no-store-content`, `purge --content`, `status`의 디스크 사용량 표시,
    운영체제 디스크 암호화에 의존한다.
- `--retention-days`를 사용하던 수동 실행은 알 수 없는 플래그로 실패한다.
- 상태 스키마 5를 저장한 뒤 구버전 바이너리로 돌아가면 미래 스키마 보호에 따라 상태를 수정하지 않는다.

## Follow-up
- 실제 400일 디스크 증가량과 `event_content` 비중을 관측한다. 사용자 장치 용량에 문제가 생기면
  임의 설정을 다시 추가하지 않고 관측값과 새 ADR을 근거로 고정 기간을 재결정한다.
