# 0016. 세션 요약(summary)을 만들지 않는다

## Status

Accepted (ADR 0005의 「`summary` 는 프롬프트 2~3번째 문장을 120자로 캡한다」를 대체한다)

## Context

ADR 0005는 세션 제목과 함께 `summary` 를 정했다. 구현은 `deriveFromPrompt` 가 제목과 요약을
한 번에 뽑는 형태로 들어갔다. 그런데 지금 상태를 훑으면 이렇다.

```
조립기      session.Session.Summary 를 채운다        ← 값이 실제로 만들어진다
저장        ── 없음 ──                               ← v3 sessions 에 summary 컬럼이 없다
조회        SessionRow.Summary = 항상 빈 문자열
소비자      프런트 0건, 바인딩 0건, CLI 0건
```

**만들어서 저장 직전에 버리고, 조회 계약에는 빈 칸으로 선언해 둔 상태다.** 절반만 구현된
결정이 계약에 남아 있다.

그런데 더 근본적인 문제가 있다. **그 값은 요약이 아니다.**

```
제목    = 프롬프트 1번째 문장
summary = 프롬프트 2~3번째 문장
```

요약은 「줄여서 다시 말하기」인데 이 구현은 「원문의 다른 조각을 잘라 붙이기」다. 문장이
하나뿐이면 빈 값이고(코드가 명시적으로 그렇게 한다 — 제목과 같은 줄이 두 번 보이지 않게),
여러 문장이면 같은 프롬프트를 앞뒤로 나눠 두 번 보여준다. 어느 쪽이든 화면에 새 정보가 없다.

진짜 요약을 만들려면 모델이 필요하다. 그런데 ADR 0003이 원문을 로컬에만 두기로 했으므로
외부 모델로 보낼 수 없고, 데몬에 로컬 모델 런타임을 넣을 계획도 없다. **지금 구조에서 만들 수
없는 값이다.**

## Decision

- **`summary` 를 만들지 않는다.** 조립기 산출(`Session.Summary`)·생성기(`SummaryRuneCap`·
  문장 범위 상수)·조회 계약(`SessionRow.Summary`)에서 모두 제거한다.
- `deriveFromPrompt` 는 제목 하나만 돌려주는 **`promptTitle`** 이 된다. 이름이 형제
  (`filesTitle`·`fallbackTitle`)와 맞는다.
- **제목 규칙은 그대로 둔다.** 첫 사용자 프롬프트의 첫 문장, 60룬 캡. 이 ADR이 뒤집는 것은
  요약 하나뿐이다.

## Alternatives Considered

### A. `summary` 컬럼을 추가해 ADR 0005를 완성한다

- 장점: 결정을 지킨다. 세션 상세 화면에 자리는 있다.
- 단점: 저장해도 화면에 쓸 것이 없다 — 값 자체가 요약이 아니라 원문의 다른 조각이다.
- 탈락 이유: 쓸모없는 값을 저장하는 비용만 늘린다. 문제는 컬럼의 부재가 아니라 값의 내용이다.

### B. 그대로 둔다

- 장점: 아무것도 안 해도 된다. 나중에 LLM 제목 생성기가 오면 자리가 있다.
- 단점: 읽는 곳 없는 필드가 계약에 남는다. ADR 0015가 `stale`·`refreshed_at` 등 네 필드를
  같은 이유로 걷어냈다.
- 탈락 이유: LLM 생성기가 온다면 그때 제목과 요약을 함께 새로 만들고 컬럼도 그때 추가한다.
  지금 빈 필드를 들고 있는 것이 그 미래를 돕지 않는다.

### C. 로컬 모델로 진짜 요약을 만든다

- 장점: 이름이 하는 말과 값이 일치한다.
- 단점: 데몬에 모델 런타임이 들어간다. ADR 0002(CGO 없이 빌드)와도 부딪힌다.
- 탈락 이유: 비용이 이 값의 가치보다 크다. 필요해지면 그때 새 ADR로 다룬다.

## Consequences/Tradeoffs

### Positive

- 조회 계약에서 항상 빈 값이던 필드가 하나 사라진다.
- 생성기·상수·테스트가 함께 사라져 제목 코드가 「제목만」 하는 코드가 된다.
- `title()` 이 반환값 셋에서 둘로 줄어 호출부가 단순해진다.

### Negative

- `sessions --json` 출력에서 `summary` 필드가 사라진다. 지금 소비자는 없지만, 이 출력을
  파싱하는 외부 스크립트가 있다면 깨진다.
- 나중에 요약이 필요해지면 결정을 다시 해야 한다. 그때는 「어떻게 만들 것인가」가 함께 정해져야
  한다 — 이 ADR이 걷어낸 것은 만들 방법 없이 이름만 있던 자리다.
