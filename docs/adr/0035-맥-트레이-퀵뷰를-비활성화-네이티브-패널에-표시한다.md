# 0035. 맥 트레이 퀵뷰를 비활성화 네이티브 패널에 표시한다

## Status

Accepted

## Context

Wails beta.11의 WebviewWindow는 NSWindow다. CollectionBehavior 설정과 앱 활성화 호출
제거만으로는 다른 앱의 전체 화면에서 퀵뷰가 보이지 않는 문제가 남았다. 일반 데스크톱에서는
표시되므로 콘텐츠 로딩과 네이티브 창 표시 정책을 구분해야 한다.

## Decision

- macOS 퀵뷰는 nonactivatingPanel 스타일의 NSPanel이 표시한다. 메인 창은 기존 NSWindow다.
- Wails WebView의 콘텐츠 뷰만 패널로 옮긴다. 원래 숨은 창은 WebView 수명과 IPC를 소유한다.
- 패널 어댑터가 네이티브 핸들·표시·숨기기·포커스·가시성을 제공한다. 트레이 위치 계산도 이 핸들을 사용한다.
- 닫기 버튼과 메인 창 열기는 같은 어댑터를 호출한다. 원래 숨은 창의 Hide를 직접 호출하지 않는다.
- 패널은 키보드 입력을 받지만 NSApp을 활성화하거나 메인 창이 되지 않는다.
- Space 이동이나 포커스 변경만으로 패널을 자동으로 숨기지 않는다.
- Wails 소스·모듈 캐시·private API는 변경하지 않는다. Windows·Linux는 기존 창을 그대로 사용한다.

## Alternatives Considered

### A. NSWindow의 CollectionBehavior만 변경한다
- 장점: 변경량이 작다.
- 탈락 이유: 사용자의 전체 화면에서 여전히 표시되지 않았다.

### B. Wails를 포크해 NSPanel 생성을 추가한다
- 장점: 창 생성 단계부터 패널을 소유한다.
- 탈락 이유: 퀵뷰 하나 때문에 전체 프레임워크 포크와 CLI 버전 관리가 추가된다.

## Consequences/Tradeoffs

### Positive
- 공개 패널 API로 전체 화면 참여와 앱 활성화를 구분한다.
- 메인 창과 다른 OS의 동작을 유지한다.

### Negative
- 원래 창과 표시 패널의 수명이 달라 닫기·가시성·이벤트를 어댑터 기준으로 검증해야 한다.
- Wails의 콘텐츠 뷰나 이벤트 전달 방식이 바뀌면 호환성을 다시 검증해야 한다.

## Acceptance Criteria

- 다른 앱의 전체 화면에서 열기·닫기·버튼·스크롤이 데스크톱 전환 없이 동작한다.
- 가시성 조회와 tray:shown/tray:hidden이 실제 패널 상태와 일치한다.
- 메인 창 열기는 퀵뷰만 닫고 메인 창을 활성화한다.
- 콘텐츠 소유권·재사용·숨기기를 검증하고 실제 화면 확인은 별도로 기록한다.
