# 0021. 설정 제거는 마지막 적용 지문으로 판정한다

## Status

Accepted — ADR 0019의 훅 제거 판정을 uninstall에 한해 보강한다. 명시적 재배선의 예약 명령 판정과 생명 주기 수집은 유지한다.

## Context

PROJ-133의 uninstall은 사용자가 설치 이후 변경한 설정을 보존해야 한다. 원본 백업 전체 복원과
관리 키 이름만으로의 삭제는 이 조건을 만족하지 못한다. 키 이름 목록에는 마지막 값이 없다.
이 결정은 telemetryctl 내부 설치 해제와 로컬 제어만 다루며 서버 manifest·enrollment 계약은 바꾸지 않는다.

## Decision

- 설치 상태 파일 옆 `managed-settings.json`에 버전·설치 ID·대상 파일·관리 항목별 SHA-256 지문을 저장한다.
  값은 파싱 후 정규화한다. 토큰 원문과 이전 설정 값은 복제하지 않는다.
- 일반 설정은 관리한 리프 키 단위, 훅은 그룹 조건과 개별 handler 단위로 비교한다.
  마지막 적용 값과 같은 항목만 지우고 변경·판별 불가 항목은 보존하여 알린다.
  남은 사용자 훅이 사용하는 `features.hooks`는 지우지 않는다.
- 신규 설치만 지원한다. 관리 키·훅의 정본은 `managed-settings.json`이며 `state.json`에 키 목록을 중복 저장하지 않는다.
- 관리 기록이 없으면 drift·제거 판정을 오류로 보고한다. 현재 설정을 자동으로 소유권 등록하지 않으며, 명시적 재배선 성공 때 기록한다.
- 설치·재배선의 상태 저장과 지문 저장 실패는 호출자에게 실패로 전달하여 설정 롤백을 유도한다.
  OTel 전용 재배선은 기존 훅 지문을 유지한다.
- drift는 status와 데몬 시작에서 표시하고 그 자체로 자동 재배선하거나 데몬을 중단하지 않는다.
- uninstall은 dry-run과 명시적 확인을 제공한다. 설정 해제 실패 시 데이터·키링 정리로 진행하지 않는다.
  설정 파일을 쓰기 직전에 재검사하며, 오류 복구용 백업은 바로 직전 파일만 대상으로 한다.
- 자동 시작을 해제하고 데몬 정상 종료를 확인한 뒤 정리한다. 종료는 별도 OS 키링 control 토큰으로
  인증한 loopback POST를 통해 요청한다. ingest 토큰으로 종료할 수 없으며 임의 PID를 kill하지 않는다.
  구버전·인증 실패·종료 시간 초과 시 중단하고 수동 종료를 안내한다.
- 데이터 삭제는 명시적으로 선택한다. 사용자 지정 디렉터리를 재귀 삭제하지 않고 알려진 파일만 지운다.
  링크·경로 충돌은 거부한다. 실행 중 CLI 바이너리 자체 삭제와 NSIS 연결은 패키징 티켓의 책임이다.
- OS 키링과 파일 삭제는 원자적 트랜잭션이 아니다. 실패한 단계와 남은 항목을 알리고 재실행 가능하게 한다.

## Alternatives Considered

### A. 설치 전 백업 전체 복원
- 장점: 구현이 단순하다.
- 단점: 설치 이후 사용자 변경이 사라진다.
- 탈락 이유: 공유 설정 파일의 소유 범위를 넘는다.

### B. 키 이름·예약 명령만으로 삭제
- 장점: 추가 기록이 없다.
- 단점: 사용자가 바꾼 endpoint·훅을 구분할 수 없다.
- 탈락 이유: 사용자 변경 보존 조건을 충족하지 못한다.

## Consequences/Tradeoffs

### Positive
- uninstall과 drift가 동일한 판정을 재사용한다.
- 서버나 벤더 설정에 소유권 표식을 추가하지 않는다.

### Negative
- 별도 기록의 일관성과 누락·손상을 관리해야 한다.
- 변경된 훅은 남을 수 있어 수동 정리 안내가 필요하다.
- 파일 재검사와 rename 사이의 외부 편집을 완전히 직렬화하지 못한다. 벤더 종료 후 실행을 권고한다.
- 지문은 소유권의 운영 근거이지 같은 OS 사용자의 악의적 변조를 막는 보안 경계는 아니다.

## Acceptance Criteria

- 사용자 설정 변경·훅 순서 변경·사용자 추가 필드를 보존한다.
- 기록·설정 파싱 실패, 쓰기 실패, 종료 실패 시 후속 파괴적 단계를 실행하지 않는다.
- 인증 없는 요청·ingest 토큰·다른 데몬 인스턴스의 종료 요청을 거부한다.
- 임시 디렉터리와 테스트 키링으로 검증하며 실제 사용자 데이터를 지우지 않는다.
