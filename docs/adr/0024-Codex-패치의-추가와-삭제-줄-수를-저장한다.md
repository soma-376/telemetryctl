# 0024. Codex 패치의 추가와 삭제 줄 수를 저장한다

## Status

Accepted (ADR 0023의 줄 수 NULL 유지 결정을 대체한다. 나머지 결정은 유효하다.)

## Context

ADR 0023으로 Codex 패치의 파일별 작업이 저장되지만, 입력 본문에 추가·삭제 줄이 있어도
`file_changes.additions`와 `deletions`가 NULL이다. 기존 전달 모델과 SQLite 컬럼은
관측된 0과 미관측을 구분할 수 있다.

## Decision

- 성공이 확인된 완전한 Codex `apply_patch` 입력에서 파일별 추가·삭제 줄 수를 계산한다.
  수치는 호출의 패치에 명시된 편집량이며, 작업 트리의 최종 diff나 순증가량이 아니다.
- 생성은 본문의 `+` 줄 수와 삭제 0, 수정과 이름 변경은 본문의 `+`·`-` 줄 수를 저장한다.
  이름만 변경하면 양쪽 모두 0이다. 문맥·제어 줄은 제외하고 추가·삭제된 빈 줄은 센다.
  여러 수정 블록은 파일별로 합산한다.
- 파일 전체 삭제는 추가 0, 삭제 NULL이다. 패치에 없는 기존 파일 내용을 읽거나 추정하지 않는다.
- 기존 문법 검증과 원문 길이 제한 전 파싱을 유지한다. 입력이 잘못되면 일부 수치도 저장하지 않는다.
- `Target`의 선택적 줄 수를 `session.FileChange`에 전달하여 기존 트랜잭션·중복 제거 경로로 저장한다.
  DB 스키마, 서버 계약, Claude 추출 규칙, 화면과 세션 합계는 변경하지 않는다.
- 신규 수집부터 적용한다. 과거 행 보정, 파일 해시, 셸 명령의 파일 변경 추적은 범위 밖이다.

## Alternatives Considered

- 모든 줄 수를 NULL로 유지하면 패치에서 관측 가능한 정보도 사용할 수 없다.
- Git diff나 현재 파일을 읽으면 다른 호출·사용자 편집이 섞이고 삭제 전 내용도 복원할 수 없다.

## Consequences/Tradeoffs

### Positive

관측된 편집량을 파일별로 저장하며 0과 미관측을 구분한다. 추가 파일 접근과 마이그레이션이 없다.

### Negative

전체 삭제의 삭제량과 과거 행은 계속 NULL이다. 패치가 명시한 편집량은 최종 파일 간 최소 diff와
다를 수 있으며, 이 수치를 세션 합계에 반영하려면 별도 집계 기준이 필요하다.

## Acceptance Criteria

생성·수정·이름 변경·전체 삭제, 빈 줄·다중 블록·큰 입력과 실패·불완전 입력을 검증한다.
OTLP JSON·Protobuf부터 SQLite까지 수치와 NULL을 확인하고 중복 수신·재시작 후 재전송에도
파일 변경 행이 늘지 않는지 검증한다.
