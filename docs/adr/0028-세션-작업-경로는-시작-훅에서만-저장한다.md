# 0028. 세션 작업 경로는 시작 훅에서만 저장한다

## Status

Accepted — ADR 0010의 OTel 원경로를 세션에 저장하는 결정을 부분 대체한다. 로컬 경로 보관 허용과 상위 전달 정책은 유지한다.

## Context

OTel 이벤트와 조립기 스냅샷은 `sessions.workspace_path`를 새 관측으로 덮어쓴다.
시작·재개 훅에서도 `cwd`를 저장하면 같은 컬럼에 두 쓰기 주체가 생긴다.
재개 훅으로 경로 B를 저장한 뒤 옛 경로 A를 가진 스냅샷이 도착하면 B가 사라진다.
이 변경은 telemetryctl의 로컬 저장에만 영향을 주며 서버 계약은 바꾸지 않는다.

## Decision

- `sessions.workspace_path`는 Claude Code·Codex의 `SessionStart` 훅만 저장·갱신한다.
- 시작·재개 훅에 비어 있지 않은 `cwd`가 있으면 원경로 그대로 저장한다. Git 루트로 변환하지 않는다.
- `cwd`가 없거나 빈 문자열이면 기존 경로를 유지한다. `SessionEnd`는 경로를 쓰지 않는다.
- OTel 이벤트·조립기 스냅샷은 세션 경로를 INSERT하거나 UPDATE하지 않는다.
- 세션 조립기와 저장 인자의 원경로 필드를 제거한다. 프로젝트 해시·이름 계산은 유지한다.
- `Event.Attr.WorkspacePath`는 기존 이벤트 중복 판별 키의 호환성을 위해 유지한다.
  이 값을 세션 저장에 쓰지 않는다. 중복 키를 바꾸면 기존 DB에 같은 이벤트가 재삽입될 수 있다.
- 기존 DB 경로는 보존한다. 훅을 받지 않은 신규 세션은 경로를 NULL로 남긴다.

## Alternatives Considered

### A. OTel은 빈 경로만 채우고 훅은 덮어쓴다

경로 누락은 줄지만 입력 순서에 따른 병합 규칙과 두 쓰기 주체가 남는다.
세션의 대표 작업 경로를 시작·재개 시점의 디렉터리로 정의하므로 채택하지 않는다.

### B. 경로 출처와 갱신 시각을 추가한다

입력 간 우선순위를 정밀하게 비교할 수 있지만 컬럼과 상태 관리가 늘어난다.
현재 요구는 여러 입력을 병합하는 것이 아니라 시작 훅의 경로를 표시하는 것이다.

## Consequences/Tradeoffs

### Positive

- OTel 저장 순서와 관계없이 훅에서 확보한 경로를 유지한다.
- 원경로를 조립기 메모리와 스냅샷으로 복제할 필요가 없다.

### Negative

- 시작 훅이 누락되거나 훅을 지원하지 않는 도구의 세션은 경로가 비어 있을 수 있다.
- 세션 중간의 디렉터리 변경은 다음 시작·재개 훅 전까지 반영하지 않는다.

## Acceptance Criteria

- 경로 속성을 가진 OTel 입력만으로 생성된 세션의 경로는 NULL이다.
- 훅으로 경로를 저장한 뒤 OTel 이벤트·스냅샷을 저장해도 경로가 유지된다.
- 경로 없는 재개와 종료는 기존 경로를 보존한다.
- 프로젝트 해시·이름 계산과 상위 전달 스크럽 테스트는 유지한다.
